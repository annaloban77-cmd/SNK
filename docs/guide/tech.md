# Техническое описание (инженерный том)

## 1. Назначение и принципы

Система нормативного контроля конструкторской документации для судостроения.
Архитектура построена на принципах P1–P7:

| Принцип | Суть |
|---|---|
| P1 | Знания — в данных (БД), не в весах модели |
| P2 | Ядро стабильно, знания обновляются часто |
| P3 | Каждое бюро = свой профиль |
| P4 | Стенд — предохранитель релиза |
| P5 | Детерминированность по умолчанию, LLM — только семантика |
| P6 | Каждое замечание объяснимо (ссылка на ГОСТ) |
| P7 | Человек принимает решение |

## 3. Поток данных

1. **Загрузка** — файл сохраняется в `uploads/`
2. **OCR** — извлечение полей штампа:
   - SVG-парсер (для бенч-семплов) — 100% точно
   - PaddleOCR (primary для сканов) — ~85% confidence
   - Tesseract (fallback) — ~30% confidence
   - VLM (last-resort при conf < 0.4) — ~85% confidence
3. **CAD-парсер** — для DXF/DWG/CDW/SLD:
   - DXF: ATTDEF блоки, TEXT entities, слои
   - DWG: UTF-16LE строки, метаданные
   - CDW/SPW: свойства файла
4. **Правила** — 460 детерминированных + семантических
5. **Post-filter** — дедупликация, confidence-aware, валидация OCR-артефактов
6. **LLM** — семантические проверки (противоречия, гипотезы)
7. **Замечания** — сохранение в БД с трассировкой до правила и ГОСТ

## 6. Механизмы качества

### Тиры тестов
| Тир | Что тестирует | Документов | Статус |
|---|---|---|---|
| Synthetic | SVG-чертежи с известными ошибками | 100 | 🟢 GREEN |
| DXF | CAD-файлы (ATTDEF + TEXT) | 20 | 🟢 GREEN |
| Realistic | Сканы с деградацией | 30 | 🔴 RED (PaddleOCR OOM) |

### Релизный гейт (P4)
GREEN только если все 3 тира проходят. Realistic не проходит в sandbox (4 ГБ RAM) — в production (8+ ГБ) PaddleOCR решит.

### db:sync
Единая команда `bun run db:sync` — идемпотентно заполняет БД: стандарты (573), правила (460), справочники (4403), тесты (150). Версия хранится в `Meta.sync_version`.

## 7. Как расширять

### Новое правило
1. Файл `src/lib/rules.ts` — добавить в `DETERMINISTIC_RULES`
2. Или через UI: раздел «Правила» → «Создать правило»
3. Запустить `bun run db:sync`

### Новый справочник
1. Создать модель в `prisma/schema.prisma`
2. `bun run db:push`
3. Создать генератор в `scripts/`
4. Добавить в `scripts/db-sync.ts`

### Новый OCR-движок
1. Реализовать sidecar (FastAPI + модель)
2. Добавить клиент в `src/lib/ocr/`
3. Добавить в цепочку в `src/lib/ocr/stamp-ocr.ts`

### Новая отрасль
1. Добавить стандарты через скрипт сидинга
2. Добавить отраслевые правила (category: shipbuilding / machinery / ...)
3. `bun run db:sync`

## 8. Развёртывание

### Docker (рекомендуется)
```bash
docker compose up -d
# Сайты: http://localhost:1111 и http://localhost:3333
```

### Ручная установка
```bash
bun install
bun run db:push
bun run db:sync
bun server.js  # запускает оба порта
```

### Требования к железу
| Параметр | Минимум | Рекомендуется |
|---|---|---|
| RAM | 4 ГБ | 8–16 ГБ |
| CPU | 4 ядра | 8 ядер |
| Диск | 20 ГБ | 50 ГБ SSD |
| GPU | нет | опционально (PaddleOCR ×3–5 быстрее) |

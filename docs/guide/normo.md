# Руководство нормоконтролёра

## 1. Назначение

Это руководство для нормоконтролёров, которые проверяют документы, работают с замечаниями и управляют правилами.

## 2. Термины

| Термин | Объяснение |
|---|---|
| **Триаж** | Распределение замечаний по важности: подтвердить / отклонить / исправлено |
| **Feedback loop** | Цикл: ложное срабатывание → тест → система больше не ошибается |
| **Правило** | Параметр проверки: что искать, где, с какой критичностью |
| **Тест (стенд)** | Набор эталонных документов с известными ошибками |

## 3. Роли и права

| Раздел | Нормоконтролёр |
|---|---|
| Документы | ✅ Загрузка, проверка |
| Замечания | ✅ Подтвердить, отклонить, исправлено |
| База знаний | ✅ Просмотр |
| Правила | ✅ Создание, отключение |
| Тесты | ✅ Запуск |
| Проекты | ✅ Создание |
| API-ключи | ❌ Только администратор |
| Аудит | ❌ Только администратор |

## 4. Порядок работы

### Сценарий 1. Триаж замечаний

![Карточка замечания](/guide/img/normo-issue-card.png)

1. Откройте документ с замечаниями
2. Для каждого замечания:
   - Прочитайте описание и ссылку на ГОСТ
   - Нажмите **«Прочитать ГОСТ»** — откроется текст стандарта
   - **Подтвердить** — замечание верное
   - **Отклонить** — ложное срабатывание
   - **Исправлено** — ошибка исправлена

### Сценарий 2. Feedback loop

![Feedback loop](/guide/img/normo-feedback.png)

1. Вы отклонили ложное замечание
2. Система создала **предложение** добавить документ в тесты
3. В разделе «Предложения» (через админа) — одобрить
4. Документ становится тестовым эталоном
5. Система больше не повторяет эту ошибку

### Сценарий 3. Создание правила без программиста

![Создание правила](/guide/img/normo-create-rule.png)

1. Раздел **«Правила»** → **«Создать правило»**
2. Заполните:
   - **Код**: уникальный (R-MY-001)
   - **Наименование**: что проверяется
   - **Категория**: stamp / material / welding / ...
   - **Метод**: deterministic (точно) или semantic (смысловой)
   - **Критичность**: высокая / средняя / низкая
   - **ГОСТ**: выберите из базы знаний
3. Нажмите **«Проверить на тестах»** — система прогонит правило по тестовым документам
4. Если результат устраивает — **«Сохранить»**

### Сценарий 4. Работа с базой знаний

![База знаний](/guide/img/normo-knowledge.png)

1. Раздел **«База знаний»**
2. Фильтр по типу (ГОСТ / ОСТ / СТО / Регистр)
3. Фильтр по категории (ЕСКД / материалы / сварка / ...)
4. Клик на стандарт — детали, пункты, связанные правила

### Сценарий 5. Чтение метрик теста

![Стенд](/guide/img/normo-bench.png)

1. Раздел **«Стенд»**
2. Метрики простыми словами:
   - **Полнота (Recall)** — какую долю реальных ошибок система нашла
   - **Точность (Precision)** — долю верных замечаний
   - **Статус**: 🟢 можно выпускать / 🟡 есть проблемы / 🔴 нельзя

## 5. Категории правил

| Категория | Что проверяет |
|---|---|
| stamp | Поля штампа (обозначение, подписи, дата) |
| material | Материалы и ГОСТ |
| welding | Сварные швы |
| format | Формат листа, рамка |
| tolerances | Допуски, посадки, шероховатость |
| specification | Спецификации |
| shipbuilding | Судостроительные требования |

## 6. Особые ситуации

### Что делать, если LLM-замечание помечено как «гипотеза»?
LLM-замечания имеют флаг `source=llm` и статус «гипотеза, требует подтверждения». Проверьте вручную — если верно, подтвердите; если нет, отклоните.

### Что делать, если правило даёт много ложных срабатываний?
1. Откройте правило в разделе «Правила»
2. Отключите тумблером
3. Отредактируйте параметры
4. Нажмите «Проверить на тестах»
5. Если тесты зелёные — включите обратно

## 7. FAQ

**В: Можно ли создать отраслевое правило?**
О: Да, выберите категорию shipbuilding и укажите ГОСТ из базы знаний.

**В: Что значит «метод semantic»?**
О: Это правило проверяет смысл, а не точное совпадение. Например, «наименование в штампе совпадает с наименованием в спецификации».

**В: Как часто запускать тесты?**
О: После каждого изменения правил или обновления системы.
